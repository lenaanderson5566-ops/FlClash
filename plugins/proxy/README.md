# FastAI system proxy ownership

`StartProxy` saves the original settings durably before applying the local proxy.
`StopProxy` restores only a saved transaction whose current values still match
FastAI's applied/original values. No record means no changes. Settings changed by
another application or the user are retained, and the obsolete record is retired.
Read, persistence or restore failure retains recovery data and prevents a new
transaction from overwriting it. The app serializes proxy operations and closes
its start gate before shutdown; platform start also attempts pending recovery.

## Platform coverage

- Windows: WinINet per-connection settings for the default LAN connection,
  including flags (PAC/auto-detect), server, bypass and PAC URL. The original and
  intended values are stored in one flushed HKCU registry value under
  `Software\FastAI\ProxyRecovery`. Explicit RAS/VPN profiles are not modified.
  Session-end handling uses the same ownership-aware restore.
- macOS: native SystemConfiguration with an authorized preferences session and
  preferences lock. Snapshots include the complete proxy dictionary, including
  whether it was absent, and use stable network service IDs in the current
  network location. Recovery restores those service IDs without switching the
  active location. Files live in the user's Application Support directory under
  `ws.fastdog.fastai/ProxyRecovery` (directory 0700, file 0600). Keychain proxy
  credentials are not queried or modified. Native registration is generated by
  Flutter; a macOS CocoaPods/Xcode build is required after this plugin update.
- Linux: GNOME/MATE gsettings and KDE kioslaverc settings, with original values
  (including absent KDE keys) saved in `~/.fastai-proxy-recovery/linux.json`
  (directory 0700, file 0600). PAC mode and existing settings are restored;
  GNOME/MATE HTTP authentication is temporarily disabled without reading or
  changing saved usernames/passwords. Missing readers/writers fail closed.

Snapshots stay local and are not telemetry. They can contain internal addresses
and PAC URLs; do not attach them to support logs. DNS/TUN ownership remains with
the existing DNS and core lifecycle coordinators.

## Limits and release validation

A killed process cannot run cleanup. Recovery runs when the app next invokes
proxy stop/start, including startup reconciliation; this is not an independent
watchdog. Historical settings overwritten by versions without snapshots cannot
be reconstructed. Windows default LAN and Linux desktop settings are global to
their OS scope, not per Wi-Fi SSID. This does not implement campus login, routing
rules, or upstream proxy authentication/chaining.

Before release, validate on the target OS: direct/PAC/manual proxies; disconnect
and normal quit; rapid mode/port changes; cancellation/permission denial; a failed
write; process termination then relaunch; an external proxy change; and network
location/service changes. macOS and Linux behavior cannot be established by a
Windows build or Dart analysis.
